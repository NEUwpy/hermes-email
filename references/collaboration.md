# 三方协作形式

人给目标并决策，Hermes 做秘书与传话，Codex 细化目标并执行。邮箱连接 Hermes 与 Codex，手机连接人与 Hermes。

## 角色与三条约定

1. **Hermes 搬运和结构化。** 保留人的原话，再附整理；不替 Codex 写代码/文章，不预审、不替人拍板。不能把投递、执行、回信生成、CLI 发送成功或人已阅读混为一谈。
2. **必要的拷问一次一个问题。** 仅对会实质改变目标、授权范围或验收标准的缺失信息提问。可合理决定的细节由 Codex 决定并说明；不要求每项任务都先问问题。停止条件是“已足以执行和验收”，允许“按你的判断”“先做一版”。人可一次答多个，Hermes 不催、不拆散原意。已有信息足够的独立工作可先推进。
3. **需要人逐字审查的文稿才按章节呈现。** 例如论文、文章草稿：Codex 交完整稿，Hermes 按原文呈现。审阅意见、汇报、进度说明等无需逐字审的交付物，Hermes 口头概述结论和需要人的动作，完整结果留在邮箱可查，不必分章。

## 问答与稿件审批

Codex 将问题或供审稿件以 `finish blocked` 登记，结果包含问题编号、目标版本、阶段、已完成动作及下一步。待审稿另带稿件路径和稿件版本；脚本保存快照。Hermes 核对当前 `handoff` 后，携人的原话和匹配的编号/版本，一次 `resume --note` 回投。命令与格式见 [protocol.md](protocol.md)。

```text
必要提问 → blocked → 人回答 → 携答案 resume → 核对有效目标 → 续做
完整供审稿 → blocked → Hermes present 原文 → 人意见 → 携意见 resume → 修订
                                      └→ 人明确通过 → resume → Codex 核对 → done
```

| 人的回答 | Hermes 的操作 | Codex 的后续动作 |
|---|---|---|
| 下一章 / 继续看 | `present --next`，转达返回原文 | 不重新接单、不修改稿件 |
| 修改这一段 | 将原话、稿件版本及行号定位以 action=revise 携答案 resume | 重新领到任务，读取旧稿与补充后修改，新稿用新版本、问题编号再次 blocked |
| 通过 | 明确通过哪个稿件版本，以 action=approve 携答案 resume | 重新领到任务，核对通过意见和实际产物后 done；不自动重写 |
| 回答问题 / 按你的判断 / 先做一版 | action=answer 携答案 resume | 在既有授权内继续，信息已足够就结束拷问 |

默认采用 **blocked 留供审稿、done 表示验收完成**：复用已有恢复队列，不引入审批执行者或另一套任务状态。普通结果可直接 done；done 后的新修改用新任务引用原任务和版本，不能追加后假称已排队。

blocked 移出“正在执行”，可以让另一封邮件执行。**可同时等待人的回答，实际一次只执行一封。** 回答重新排队也不保证立即抢占当前任务。

## 原文呈现与位置

Hermes 在人查询/回复时读取本地回信，再调用 `present`；无需新增模型轮询进程。第一次返回当前块，`--next` 推进，普通重试返回同一位置。脚本记录稿件版本和原文行号；完整稿件快照、散列、阅读位置都保存在任务目录。

默认按标题单元呈现，超长章节按完整段落分块。原文、论据、限定条件、公式、代码和表格保留；不以摘要替代逐字审稿。每块带任务、稿件版本与行号，意见可对应回完整稿。代码围栏和连续表格/段落不从中截断；单个不可分块超过限制时返回 oversized，Hermes 保持原文，通过附件/可读文件呈现或与人协商，不伪称已满足手机长度限制。

“粗/细”若只是合并或切小阅读块，由 Hermes 用 `--max-chars` 调整当前块，不回投 Codex。若人指内容概括、展开或压缩，或含义不明，先作一次最小澄清；内容要求回投，不能由 Hermes 改写原稿。阅读到末尾不会自动通过，明确验收才恢复执行。

## Hermes 直接转达，主动提醒默认关闭

状态变化直接保存到“回信/记录”，供内部审计，默认不进入投递队列、不调用 hermes send。旧“回信/待发送”中的文件迁入内部记录，保留原文及已有送达证据，不能伪记已发送。

Hermes 在人问进度、回复，或当前活跃回合需要了解任务时，调用一次 brief --task-id，取得当前状态、新结果标记、是否需要回答、要点及结果路径；阅读必要的完整结果后，像助手一样直接用自己的话告诉人，不转发回执。逐字审稿仍用 present 保真；其他结果口头概述。阅读下一块由人触发，不一次推完章节。

新结果标记表示相对上次本地读取的变化，不证明人已收到或已阅读。默认不常驻轮询、不增加后台进程；人未询问且 Hermes 没有活跃回合时，不保证立即得知完成。

只有人明确需要离线主动提醒时才 push on，再手动执行一次 notify。开启后只提醒新状态变化，不补推历史审计记录；仅发送需要回答/待审稿/结果/失败的短提示（最多1200字符）。结束提醒可 push off。原 P2-3 的短提示是这个可选路径，默认路径为 Hermes 查询后直接转达。发送失败或未知仍需核实，不能伪记已发送。

## 改方向、撤回与迟到回答

- 回复记录 task_id、question_id、goal_version，涉及稿件还带 artifact_version，正文保留人的原话。每轮等待使用新的问题编号；可用 answer_id 保证同一回答重试只记一次。
- resume 前读取当前状态和 handoff。脚本拒绝不匹配的问题/版本和已撤回任务；“下一章”不能用 resume。
- 改方向用 action=redirect，写 previous_goal_version 与新的 goal_version，正文说明哪些旧要求被替代、哪些仍保留。执行中用 update；等待补充/失败中用携新目标 resume。旧目标的迟到回答不恢复新目标。旧记录留存，不删除。
- 撤回某一项任务用 `cancel --task-id --note`，不改变邮箱全局模式。尚未接单的撤回任务不再领取；等待任务不能恢复。执行中的撤回在自然检查点响应，保留已做动作，finish failed 释放队列，不保证瞬间撤销外部副作用。
- 全局暂停用 `mode paused`；停止用 `mode stopped`。Codex 在自然检查点读取控制、撤回及最新补充；不可逆动作前再确认当前有效目标及授权。重新授权已撤回的工作须发新任务。

## 失败与续做

blocked/failed 结果记录阶段、稿件版本（若有）、已完成动作和下一步。resume 保存历史结果及 handoff；重新接单后读取 history_results、handoff、有效补充、当前 Git/文件状态再续做。另一项任务可能已在同一项目改过文件，快照保留原稿供核对，不代表工作区仍是旧版本。

失败重试用 action=retry，并先检查是否已经发生外部动作。运行中所有权恢复沿用 recover 的旧会话停止及检查点要求；不能统一从头重跑。旧版没有问题/版本字段的邮件仍可用原命令，但需 Hermes 人工核对上下文，不能声称有自动迟到答案校验。
